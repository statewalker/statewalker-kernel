# fragments

The twelve core fragments of the platform (`system.commands`, `system.workbench`, `system.settings`, `system.appearance`, `system.l10n`, `system.a2ui`, `system.security`, `system.agents`, `system.fragments`, `system.host`, `system.profile`, `system.tasks`). Only `system.agents` can be disabled; the kernel refuses to disable any other (`DISABLEABLE_CORE`). Each fragment is a folder with its `fragment.jsonc` and its aspects (`server/`, `client/`, `agent/<plugin>/`).

So far: [system.commands](system.commands), the command bus and the `commands` and `keybindings` points; [system.workbench](system.workbench), the `views`, `layouts`, `menus`, `notifications`, `dialogs`, `statusbar` and `activitybar` points and the workbench (menu bar, context menus, palette, keyboard shortcuts, dialogs, notifications and bars around one dockview of left, right, bottom and centre zones, with a dock for surfaces; drawers on a tablet, one panel and a bottom tab bar on a phone; a layout per device mode); [system.security](system.security), the `capabilities` point, the capabilities only system code issues, and the gate of calls from agents, peers and sandboxes (grants and the user's Allow/Ask/Block policy); [system.a2ui](system.a2ui), the `catalog` point and A2UI 1.0 surfaces; [system.appearance](system.appearance), the `branding` and `themes` points and the shadcn tokens of the active brand, light and dark; [system.host](system.host), the `host-services` point: the clipboard, the file picker and the URL state, the host's own or a fragment's; [system.profile](system.profile), the user's profile on the device (the kernel's records, the workbench's layouts per device mode, the settings values) and the secrets vault (encrypted, unlocked with a password or a passkey, its key optionally remembered on the device, locked when unreadable); [system.l10n](system.l10n), the `l10n` point (message bundles per locale, namespaced per fragment, and language packs) and the interface language, switched live; [system.settings](system.settings), the `settings` point (each fragment's settings as a JSON Schema) and one settings view, its values in the profile; and [system.tasks](system.tasks), the host's task queue: commands exposed as `task` served from it, and `publish`, `cancel` and `job`. Each core fragment is also a private workspace package whose code the host runs when the kernel activates the fragment.

The fragment model is specified in statewalker/statewalker-root#215.
